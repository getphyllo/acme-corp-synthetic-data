# Acme Corp — Report Pack

A set of **80 realistic business documents** (PPTX / PDF / DOCX / XLSX) generated on top of the Acme
synthetic dataset. They exist so the Clayface demo and any document-ingestion / RAG / training pipelines
have **format-diverse, internally-consistent source material** to test against — the kind of files a CPG
company actually produces, every figure traceable to a table in this repo.

- **Reports 01–10** — the original pack (PPTX/PDF/DOCX/XLSX), focused on the Crunchwell Louisiana decline
  and the ProteinPeak Q2 launch. Hand-built, generated 2026-06-25.
- **Reports 11–40** — a 30-document **PDF expansion** covering the full spread of documents a consumer-goods
  company runs on: enterprise & board reviews, annual and long-range plans, brand plans, retailer joint
  business plans, and the functional reviews (S&OP, supply chain, trade, media, RGM, category, shopper,
  competitive, innovation). Generated by a deterministic Python generator in [`generators/`](./generators/).
- **Reports 41–60** — a 20-deck **PPTX expansion**: the management presentations that sit behind the same
  decisions — QBRs, board pre-reads, brand plans, stage-gate reviews, functional reviews and retailer JBPs.
- **Reports 61–80** — a 20-document **DOCX expansion**: the written artefacts around those decisions —
  plan narratives, decision memos, policy documents, an agency brief, S&OP minutes, an after-action
  review, action plans, negotiation briefs and a competitive playbook.

> All documents are marked **Internal · Confidential — Acme Corp synthetic demo data**. The data and the
> people in it are fictional. Do not use for any real CPG decision-making.

## Grounding

Every headline number in reports 11–80 traces to a parquet/seed table in this repo or to the canonical
scenario docs. Forward-looking figures (FY27+ targets, H2 forecasts, spend reallocations) are labelled
in-document as *target* / *plan* / *planning estimate*. Where two instruments won't tie to the decimal
(e.g. NielsenIQ value share vs the canonical Mass/Grocery peak-to-trough LA headline of 6.4% → 3.0%), both
are shown and reconciled in-doc. See [`generators/FACTS.md`](./generators/FACTS.md) for the full grounded
fact sheet the reports are built from.

Reports 41–80 also **cross-reference each other by number** ("see the CFO read, Report 74"), and the same
figure computed in two documents comes from the same query helper in `generators/qlib.py` — so a deck and
its companion memo cannot drift apart.

## Regenerating reports 11–80

The 70 documents are produced by a deterministic Python generator (mirroring how `generator/generate.py`
produces the data). Don't hand-edit the outputs — change the generator and re-run. Full rebuild is ~11s.

```bash
python -m venv .venv && .venv/bin/pip install pandas pyarrow duckdb reportlab matplotlib python-pptx python-docx
.venv/bin/python reports/generators/build_all.py     # rebuilds all 70 documents + charts
```

Generator layout ([`generators/`](./generators/)):

- `lib.py` — shared toolkit: DuckDB access, PDF document builder (cover, KPI strips, tables, callouts,
  recommendations), and the chart helpers (line / bar / grouped / stacked / waterfall / donut).
- `pptx_lib.py` — `Deck`: the 16:9 slide layouts (title, agenda, exec summary, KPI tiles, chart,
  two-chart, chart+table, chart+bullets, table, two-column, risk, recommendations, closing).
- `docx_lib.py` — `Memo`: the written-document blocks (masthead, at-a-glance strip, headings, body,
  bullets, tables, callouts, images, decision log, risks, recommendations, approvals).
- `qlib.py` — the grounded query helpers shared by decks and documents, so one number is computed one way.
- `corporate.py` · `strategy.py` · `brands.py` · `brands2.py` · `functional.py` · `insights.py` ·
  `customers.py` — PDFs 11–40, one module per theme, one builder function per report.
- `decks_a.py` (41–51) · `decks_b.py` (52–60) — the PPTX builders.
- `memos_a.py` (61–70) · `memos_b.py` (71–80) — the DOCX builders.
- `build_all.py` — runs every builder.
- `FACTS.md` — the grounded fact sheet. `STYLE.md` — the authoring / API contract.
